# TinyNPU v0.3.0-alpha

TinyNPU v0.3.0-alpha adds a software-accessible APB3/MMIO interface
around the existing 4×4 signed INT8 matrix-multiplication accelerator.

## Major additions

### APB3 peripheral interface

Added a 32-bit, zero-wait-state APB3 slave wrapper:

- `rtl/tinynpu_apb.sv`

The wrapper translates APB register transactions into the existing
TinyNPU core interface without modifying the core's mathematical
behavior.

### Register map

| Address | Register | Access |
|---:|---|---|
| `0x000` | `CONTROL` | Write |
| `0x004` | `STATUS` | Read |
| `0x008` | `CONFIG` | Read |
| `0x010` | `A_INDEX` | Read/write |
| `0x014` | `A_DATA` | Read/write |
| `0x018` | `B_INDEX` | Read/write |
| `0x01C` | `B_DATA` | Read/write |
| `0x020` | `C_INDEX` | Read/write |
| `0x024` | `C_DATA` | Read |

Current CONFIG value:

```text
0x10200804
```

This reports:

- matrix dimension: 4
- operand width: 8 bits
- accumulator/result width: 32 bits
- matrix element count: 16

### Software-visible status

The wrapper provides:

- `BUSY`
- sticky `DONE`
- sticky `ERROR`
- `OPERANDS_READY`

All 16 A elements and all 16 B elements must be loaded before START is
accepted.

### Error handling

`PSLVERR` is generated for:

- unaligned accesses
- undefined addresses
- writes to read-only registers
- indexes greater than 15
- operand writes while BUSY
- START with incomplete operands
- START while BUSY

Rejected transactions also set sticky ERROR status.

### Reusable operands

Matrix A and B remain loaded after computation. Software can clear
sticky DONE and begin another calculation without rewriting the
operands.

## Verification additions

Added:

- `tb/tinynpu_apb_smoke_tb.sv`
- `tb/tinynpu_apb_compute_tb.sv`
- `tb/tinynpu_apb_assertions.sv`
- `tb/tinynpu_apb_coverage.sv`

The APB verification covers:

- reset behavior
- CONFIG register contents
- valid and invalid register accesses
- unaligned transactions
- signed INT8 operand readback
- incomplete-operand START rejection
- complete 4×4 matrix multiplication
- BUSY and sticky DONE behavior
- writes rejected while BUSY
- all 16 signed INT32 results
- sticky status clearing
- two computations without reloading operands

## Current project scope

TinyNPU currently includes:

- parameterized signed multiply-accumulate unit
- sequential 4×4 signed INT8 matrix multiplication
- signed INT32 accumulation and results
- APB3/MMIO peripheral wrapper
- Python/NumPy golden model
- directed and randomized verification
- assertions and functional coverage
- lint and synthesis checks
- automated CI

## Future work
